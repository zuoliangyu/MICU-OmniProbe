# AI 数据桥接与可视化调参指南

MICU-OmniProbe 可以把串口、RTT 和蓝牙（BLE）收到的文本行，以及解析得到的原始标准样本，以实时 NDJSON 数据流提供给本机 AI 工具。AI 与文本区、波形和 FFT 来自同一批输入。数值样本不应用页面中的滤波配置，因此 AI 拿到的是原始数据，适合分析和调参。

三个工作台共用同一个桥接服务和端口，每条消息都带 `source` 字段（`serial` / `rtt` / `ble`）标明来源。

## 开始使用

1. 进入串口、RTT 或蓝牙工作台，连接设备并开始接收。
2. 需要分析波形时，从工具栏“更多”中点击“智能启用”或打开图表配置，确认通道、单位和采样率正确。只分析文本时可跳过。
3. 在同一个“更多”菜单中打开“AI”，设置端口（默认 `8765`）并启动。在任一工作台启动后，其他工作台看到的是同一个服务。
4. 启动后服务只监听 `127.0.0.1`，不会向局域网暴露。
5. 点击“复制监听命令”，在项目根目录执行复制出的命令。命令已带上当前工作台的 `--source`。

持续查看某个来源的标准数据流：

```bash
python skills/micu-omniprobe-ai/scripts/client.py watch --port 8765 --source rtt
```

采集 5 秒并生成适合 AI 阅读的统计摘要：

```bash
python skills/micu-omniprobe-ai/scripts/client.py snapshot --port 8765 --source rtt --seconds 5
```

省略 `--source` 时接收全部来源。同时有多个工作台在收数据时，建议总是指定来源，避免不同设备的通道混在一起统计。

摘要包含样本数、采样率、每个通道的最小值、最大值、均值、标准差和最新值，以及采集窗口内最近 200 行文本。`sources` 字段列出窗口内实际收到数据的来源。即使没有可解析的数值，只要收到了文本行，采集也会成功。

## 数据来源

| 来源     | `source` | 文本行                                   | 数值样本         |
| -------- | -------- | ---------------------------------------- | ---------------- |
| 串口     | `serial` | 收发两个方向，`direction` 为 `rx` / `tx` | 串口图表解析结果 |
| RTT      | `rtt`    | 各上行通道，行内带 `channel` 通道号      | RTT 图表解析结果 |
| 蓝牙 BLE | `ble`    | 收发两个方向                             | 蓝牙图表解析结果 |

经典蓝牙 SPP 设备在系统中是虚拟串口，连接后会进入串口工作台，因此按 `serial` 来源处理。

RTT 文本区“暂停显示”只影响界面，AI 仍会收到暂停期间的全部数据。

各工作台复用现有的数据解析，支持：

- JSON 数值字段
- CSV / 自定义分隔符
- `key=value`
- 正则表达式
- JustFloat / VOFA RawData
- 自动识别

文本行不依赖图表解析，包含时间戳、方向和原文，因此 `no_signal`、错误原因和结论等非数值诊断内容也能交给 AI。单行超过 16384 个字符时会截断，并以 `truncated: true` 标记。

数值样本仍依赖数据解析。解析未启用或没有解析出有效数值时，客户端不会收到 `samples` 消息，但仍可收到 `text` 消息。解析独立于当前打开的展示视图；需要分析波形时，可先确认解析成功数持续增加。

服务端输出两种数据消息：

- `type: "samples"`：解析后的数值通道与样本。
- `type: "text"`：文本区对应的行，字段为 `timestamp`、`direction`、`text`、`truncated`，RTT 另带 `channel`。

`sampleRateHz` 为 `0` 表示没有配置采样率。数据可能成批到达，AI 不应把每批数据的到达间隔当作真实采样周期；需要频率、相位或 FFT 分析时，请在对应工作台的图表配置中填写实际采样率。

## 允许 AI 写入参数

桥接启动后默认为只读。写权限按来源分别授权：在哪个工作台的“AI”面板打开开关，就只允许 AI 写入那个目标。

| 来源     | 面板开关                | 写入位置                                       |
| -------- | ----------------------- | ---------------------------------------------- |
| 串口     | 允许 AI 写串口          | 当前连接的串口                                 |
| RTT      | 允许 AI 写 RTT 下行通道 | 指定的下行通道，固件需调用 `SEGGER_RTT_Read`   |
| 蓝牙 BLE | 允许 AI 写蓝牙特征值    | 蓝牙发送栏当前选中的可写特征值，写入方式也相同 |

面板会提示 AI 当前还能写入哪些其他来源，方便确认没有遗留授权。

发送文本命令：

```bash
# 串口
python skills/micu-omniprobe-ai/scripts/client.py write --port 8765 --text "kp=0.20" --line-ending lf

# RTT 下行通道 0
python skills/micu-omniprobe-ai/scripts/client.py write --port 8765 --source rtt --channel 0 --text "kp=0.20"

# 蓝牙
python skills/micu-omniprobe-ai/scripts/client.py write --port 8765 --source ble --text "kp=0.20"
```

支持 `none`、`lf`、`crlf`、`cr` 四种换行，单条命令最多 1024 字节。命令成功后返回包含字节数的 ACK；RTT 的字节数表示已进入下行队列。未授权、设备未连接、RTT 未运行、下行通道不存在、蓝牙未选择可写特征值或命令不合法时，会返回错误。

建议采用以下调参顺序：

1. 保存当前安全参数和恢复方法。
2. 采集固定时间窗，记录调参前指标。
3. 一次只改一个参数，并限制合法范围和步长。
4. 发送前确认完整命令。
5. 调整后采集相同时长的数据进行对比。
6. 波形失稳、饱和或通信异常时立即停止，并恢复上一个安全值。

不用时关闭写权限；停止桥接会自动关闭所有来源的写权限。

## Codex Skill

项目提供 `skills/micu-omniprobe-ai`。将该目录安装到 Codex Skills 后，可以用 `$micu-omniprobe-ai` 要求 AI 观察串口、RTT 或蓝牙数据，比较调参前后指标，并在用户确认后执行受控写入。

串口、RTT 和蓝牙工具栏的“更多”菜单都提供“Skill”入口，可直接复制 Skill 的 GitHub 链接，或复制已经带上当前桥接端口、数据来源和安全要求的安装文案，再粘贴给用户自己的 AI。软件不会自动修改任何 AI 工具的安装目录。

Skill 不会绕过应用的写权限。没有参数边界、恢复值或明确确认时，它只应给出建议。

## 常见问题

**客户端能连接但没有样本**

- 确认对应工作台正在接收，且 `--source` 与工作台一致。
- 如果能看到 `textLines` 但 `sampleCount` 为 `0`，说明文本桥接正常，只是没有解析出数值。
- 确认该工作台的数据解析已启用且解析成功数持续增加。
- 检查通道字段和数据格式是否匹配。

**提示端口占用**

换一个 `1024-65535` 范围内的端口，或关闭正在使用该端口的本机程序。

**丢弃批次持续增长**

表示客户端读取速度跟不上数据产生速度。桥接会丢弃该客户端的旧批次，确保不会拖慢数据接收和界面。可降低设备输出频率、减少通道，或缩短单次观察时间。

**写命令被拒绝**

确认设备已连接，并在对应工作台的“AI”面板中打开该来源的写权限。每次重新启动桥接后都需要重新授权。RTT 还需要固件提供下行通道（`SEGGER_RTT_MAX_NUM_DOWN_BUFFERS` 大于 0）并及时读取；蓝牙需要先在发送栏选中可写特征值。
