# 蓝牙用户手册

MICU-OmniProbe 蓝牙模式提供两种工作方式：

- **BLE 中央设备**：扫描 → 连接 → 订阅 Notify → 收发数据 → 实时图表
- **经典蓝牙 SPP**：列出系统已配对设备的虚拟 COM，一键跳转到串口模式（复用全部串口能力）

本手册介绍主要使用流程与常见问题。

## 适用场景

- 通过 Nordic UART Service (NUS) 跟 nRF52、ESP32、CH582 等芯片做无线串口
- 调试任何使用 GATT Notify / Indicate 的自定义协议
- 在波形 / FFT 工作台里观察传感器数值（加速度、温度、电池电压等）

> 蓝牙模式不依赖调试探针，可独立于烧录 / RTT / 串口模式使用。

## 准备工作

| 平台             | 要求                                                            |
| ---------------- | --------------------------------------------------------------- |
| Windows 10 1809+ | 系统自带 BLE 栈，无需驱动                                       |
| Linux            | BlueZ 5.x；权限不足时把账户加入 `bluetooth` 组                  |
| macOS 10.13+     | 首次使用前在「系统设置 → 隐私与安全 → 蓝牙」中允许 MICU-OmniProbe |

## 进入蓝牙模式

- 左侧模式轨道点击「蓝牙」
- 或者使用快捷键 `Ctrl + 4`

进入后在右侧配置检查器顶部选择 **BLE** 或 **经典蓝牙 SPP**。模式偏好会自动记住。

## 扫描与连接

1. 在右侧「设备扫描」区域点击「扫描」按钮，开始 6 秒主动扫描
2. 扫描结果按是否有名称、信号强度（RSSI）排序显示，含 MAC 地址 / 平台 ID 与 RSSI
3. 点击任意设备一项即可发起连接
4. 连接成功后程序会自动发现 GATT 服务，并优先尝试匹配 Nordic UART Service

> **NUS 自动识别**：如果设备暴露了 NUS，连接完成后 RX/TX 特征值会自动选好，可直接点「开始接收 (Notify)」。

## 选择特征值

如果设备没有 NUS，或者你想手动指定，可在「特征值」卡片里浏览所有服务和特征值。每个特征值会显示属性 tag：

| 属性         | 含义                                     |
| ------------ | ---------------------------------------- |
| **R**        | Read（可主动读取）                       |
| **W**        | Write（可写入，需要响应）                |
| **WnR**      | Write Without Response（可写入，无响应） |
| **Notify**   | 可订阅，设备主动推送                     |
| **Indicate** | 可订阅，设备推送并要求确认               |

为每个特征值提供两个按钮：

- **作为 Notify**：把当前特征值设为接收订阅源（仅 Notify / Indicate 可选）
- **作为 Write**：把当前特征值设为发送目标（仅 W / WnR 可选）

## 接收数据

1. 选好 Notify 特征值后，点击「开始接收 (Notify)」
2. 数据会持续刷新到主区域
3. 工具栏支持：
   - **视图切换**：仅文本 / 分屏 / 仅图表
   - **搜索框**：按关键词过滤文本区
   - **更多**：集中使用智能启用、波形 / FFT、分屏方向、HEX / Text、自动滚动、冻结图表和图表配置
   - **独立窗口**：图表区可弹出为单独窗口，切换到 RTT 或串口工作台后仍持续同步
   - **右键保存**：在文本区右键，将当前筛选结果全部保存为 TXT
   - **清空**：清空文本与图表数据

## 发送数据

底部发送栏可向 Write 特征值写入数据：

1. 在右侧「特征值」区域把目标特征值选为 Write（NUS 自动识别后可跳过）
2. 在发送栏输入文本，回车发送
3. 点击发送栏左侧「选项」可配置：
   - **HEX 模式**：开启后输入框接收形如 `48 65 6C 6C 6F` 或 `4865 6C6C 6F` 的十六进制
   - **编码**：UTF-8 / ASCII
   - **换行符**：None / LF / CRLF / CR
   - **写入响应**：自动 / Write（需响应）/ Write Without Response（无响应）

> 默认「自动」会优先使用支持响应的 Write；如果设备只支持 WnR，会自动降级。

## 图表与解析

BLE 接收的字节流走的是和 RTT / 串口完全相同的解析链路，因此：

- 单数值（如 `printf("%d\n", v)`）→ 波形示波器
- CSV（`%.1f,%.1f,%.1f\n`）→ 多通道波形
- JSON（`{"temp":25.1,"humi":48}`）→ 多通道波形
- XY 数据（`x,y\n`）→ XY 散点图
- 颜色标记和 ANSI 转义同样生效

收到数值数据后，可在 `更多` 中点击 `智能启用` 自动识别格式，也可打开 `图表配置` 手动调整。`波形` / `FFT` 会显示当前激活状态；再次点击已激活的按钮会收起图表，但继续在后台解析和缓存数据。

详细参数请参考 [RTT 图表指南](RTT_CHART_GUIDE.md)，BLE 模式下的工作台界面与之一致。

RTT、串口和 BLE 使用不同的窗口标识、数据快照和控制状态，三个图表窗口可以同时打开。冻结、清空、修改配置或收回窗口只影响对应的数据源；冻结期间后台仍继续缓存数据。

## 常见问题

**扫描不到设备**

- 确认目标设备处于广播状态（不是处于已连接到其他主机）
- macOS 第一次使用必须给蓝牙权限，否则扫描结果一直为 0
- Linux 上检查 `bluetoothctl power on` 是否打开

**连接成功但 NUS 没自动识别**

- 设备的服务 UUID 不是标准 NUS（`6E400001-...`），属于自定义协议；请手动选择 Notify / Write 特征值

**收不到数据**

- 检查是否点了「开始接收 (Notify)」
- 部分设备需要先写一条命令才会开始推送，可在发送栏发起一次 Write
- 选择的特征值实际不支持 Notify（属性栏没有 Notify / Indicate tag）

**写入报错**

- 切到「选项 → 写入响应 → 无响应」试试，部分外设只支持 Write Without Response
- 检查写入数据长度是否超过当前 MTU（默认 23 - 3 = 20 字节）；超长协议建议拆包

## 经典蓝牙 SPP 模式

SPP（Serial Port Profile）是经典蓝牙的串口轮廓，常见于 HC-05/06、车载 OBD、串口蓝牙模块等老设备。SPP 设备配对后操作系统会把它映射成虚拟串口（Windows: COMxx，Linux: `/dev/rfcommN`，macOS: `/dev/tty.*Bluetooth*`），所以本应用直接复用「串口模式」的全部能力。

### 使用步骤

1. **在系统蓝牙设置中和目标设备完成配对**
   - Windows：设置 → 蓝牙和其他设备 → 添加设备
   - Linux：`bluetoothctl` 或 GNOME/KDE 蓝牙设置；配对后用 `rfcomm bind 0 <BDADDR>` 绑定到 `/dev/rfcomm0`
   - macOS：系统设置 → 蓝牙 → 配对
2. 进入蓝牙模式，左上「工作模式」选择 **经典蓝牙 SPP**
3. 「SPP 虚拟串口」卡片会自动列出蓝牙虚拟 COM；如果没出来就点「刷新」
4. 点击端口右侧「连接」按钮：应用会用当前串口默认参数（默认 115200 bps）连接并自动跳转到串口工作台

### SPP 后的工作流

跳转到串口工作台后：

- 收发数据全部走系统蓝牙栈，应用不感知传输细节
- 终端视图、收发分屏、文本/HEX 切换、发送历史、波形/FFT 工作台都直接可用
- 如果发现波特率配错、需要换设备，回到串口工作台调整即可（同时也会回到蓝牙模式重新选 SPP）

### SPP 故障排查

**「SPP 虚拟串口」列表是空的**

- 设备还没在系统中配对——SPP 需要系统级配对，应用不能代劳
- Linux 上配对完了但还没 `rfcomm bind`
- 设备只支持 BLE，没有 SPP 轮廓——切回 BLE 模式即可

**点击「连接」失败**

- 设备没开机或不在主机蓝牙范围内
- 同一个 SPP 端口已被其他程序占用（关掉占用方再试）
- 部分设备配对后需要先按一次配对键才接受连接

## 已知限制

- BLE 只做 Central 角色（即 MICU-OmniProbe 作为主机扫描和连接外设）
- 不支持 PIN 配对绑定（pairing with bonding）；如设备要求 PIN，请在系统蓝牙设置中完成
- SPP 不在应用内做配对，必须先用系统蓝牙设置配对成功
- 不提供 MTU 调整 UI（依赖系统协商默认值）
- 一次只能同时订阅一个 Notify 特征值
