# 控制面板组件

控制面板现在是左侧导航中的独立工作台，可选择“串口”或“RTT”作为数据来源。BLE 会显示在来源列表中，但当前版本暂未实现接入。

本手册覆盖控制面板当前的全部 15 种组件，重点说明两件事：

1. 发送组件会让设备实际收到什么。
2. 显示组件要求设备按什么格式输出。

## 30 秒上手

先在串口或 RTT 工作台完成连接和数据解析，再进入左侧“面板”工作台选择对应数据来源。切换到面板不会中断正在运行的串口、模拟数据或 RTT 数据源。

发送命令：

1. 添加“发送按钮”。
2. 保持默认命令 <code>PING</code> 和 TEXT 格式。
3. 运行后点击按钮，设备默认收到 <code>PING\n</code>。

显示设备温度：

1. 让设备连续输出 <code>{"temp":25.3}\n</code>。
2. 在对应数据源工作台的“数据”页选择 JSON，确认预览出现 <code>temp</code>，点击“应用解析”。
3. 添加“接收数值”，把“接收通道 key”填为 <code>temp</code>。

## 组件总览

| 类别     | 组件                                                     | 数据方向               | 默认格式           |
| -------- | -------------------------------------------------------- | ---------------------- | ------------------ |
| 发送     | 发送按钮、开关、滑块、参数输入、参数微调、摇杆、命令序列 | 应用 → 设备            | TEXT、UTF-8、LF    |
| 数据显示 | 能量槽、接收数值、状态灯                                 | 设备 → 解析通道 → 组件 | 任一受支持解析格式 |
| 日志     | 串口日志                                                 | 原始 RX/TX 行 → 组件   | 不要求数值解析     |
| 可视化   | YT、FFT、XY、IMU 3D                                      | 设备 → 解析通道 → 组件 | 任一受支持解析格式 |

所有显示组件都复用当前数据来源“数据”页的同一份解析结果，不会各自再解析一次。切换来源不会删除布局，但来源之间的通道 key 需要保持一致。完整输入格式见 [输入数据解析格式](DATA_FORMAT_GUIDE.md)。

发送组件当前只支持串口数据源。选择 RTT 时，发送按钮、滑块、摇杆等组件会保持禁用；BLE 数据源暂未实现。

## 发送组件共用规则

### TEXT 格式

默认发送设置是：

```text
编码：UTF-8
换行：LF
格式：TEXT
```

因此组件内容为 <code>PING</code> 时，设备收到的字节是：

```text
50 49 4E 47 0A
 P  I  N  G \n
```

TEXT 组件沿用发送栏的全局编码和换行设置，可选 UTF-8、ASCII、GBK，以及无换行、LF、CRLF、CR。组件属性中的命令通常不要自行写换行，应用会按全局设置追加。

### HEX 格式

HEX 内容会先移除空白，再按每两个十六进制字符转换成一个字节：

```text
AA 01 FF  →  [0xAA, 0x01, 0xFF]
```

- 允许空格、换行等空白。
- 不允许 <code>0xAA</code> 形式。
- 非十六进制字符或奇数个字符会报错。
- HEX 模式忽略文本编码和全局换行，不会自动追加任何字节。
- 模板占位符只是字符串替换，不会自动把十进制数转换成十六进制。

滑块、微调和摇杆默认适合 TEXT。若它们使用 HEX，替换后的完整字符串必须仍是合法偶数位十六进制；需要复杂二进制封包、校验和或数值编码时，当前版本暂不可用，建议由设备端使用文本协议，或先使用固定 HEX 命令组件。

## 接收组件共用规则

推荐设备每次采样输出一行 JSON：

```text
{"temp":25.3,"battery":78,"ready":1}
```

默认数据流：

```text
设备输出 → 接收分帧 → 数据解析 → {temp, battery, ready}
                              ├→ 接收数值
                              ├→ 能量槽
                              └→ 状态灯
```

也可以使用 KV、分隔符、正则或 JustFloat。组件只关心最终通道 key，不关心它原来是哪种格式。

<a id="button"></a>

## 发送按钮

### 默认配置

| 属性 | 默认值            |
| ---- | ----------------- |
| 命令 | <code>PING</code> |
| 格式 | TEXT              |
| 触发 | 每次点击一次      |

设备默认收到：

```text
PING\n
```

数据流：<code>点击 → PING → UTF-8 编码 → 追加 LF → 设备</code>。

### 常用配置

- 复位命令：<code>RESET</code>
- 查询版本：<code>AT+GMR</code>
- 固定 HEX 帧：切换到 HEX，填写 <code>AA 01 00 55</code>

### 排查

- 点击无反应：先确认数据源已连接。
- 设备不识别：核对设备要求的换行符。
- HEX 报错：去掉 <code>0x</code>，保证字符数为偶数。

<a id="toggle"></a>

## 开关

### 默认配置

```text
开启命令：LED=1
关闭命令：LED=0
格式：TEXT
```

设备分别收到：

```text
LED=1\n
LED=0\n
```

数据流：<code>切换状态 → 选择开启/关闭命令 → 编码并追加换行 → 设备</code>。

开关状态保存在控制面板配置中，但它不读取设备真实状态，也不会自动等待 ACK。若设备可能从其他入口改变状态，当前版本的开关不会自动同步。

<a id="slider"></a>

## 滑块

### 默认配置

| 属性     | 默认值                   |
| -------- | ------------------------ |
| 模板     | <code>PWM={value}</code> |
| 范围     | 0–255                    |
| 步长     | 1                        |
| 初始值   | 0                        |
| 发送方式 | 松手发送                 |

拖到 128 时，设备默认收到：

```text
PWM=128\n
```

<code>{value}</code> 会被当前数值替换。连续发送模式在拖动时固定按 100ms 节流，避免占满串口。

### 设备端示例

```c
// 收到一行后：
if (sscanf(line, "PWM=%d", &pwm) == 1) {
    set_pwm(pwm);
}
```

### 排查

- 设备收到的值没有变化：模板必须包含 <code>{value}</code>。
- 发送太频繁：改回“松手发送”。
- HEX 模式出现无效格式：数值不会自动转换为二进制或十六进制，优先使用 TEXT。

<a id="input"></a>

## 参数输入

### 默认配置

```text
模板：{value}
初始内容：空
格式：TEXT
```

输入 <code>hello</code> 后按 Enter 或点击发送，设备默认收到：

```text
hello\n
```

模板可增加固定前缀，例如 <code>NAME={value}</code>；输入 <code>motor</code> 后设备收到 <code>NAME=motor\n</code>。

输入组件不校验内容语义。TEXT 可输入任意文本；HEX 必须让替换后的完整内容满足 HEX 共用规则。

<a id="stepper"></a>

## 参数微调

### 默认配置

| 属性   | 默认值                     |
| ------ | -------------------------- |
| 模板   | <code>PARAM={value}</code> |
| 范围   | 0–100                      |
| 步长   | 1                          |
| 初始值 | 0                          |

数值为 42 时，设备默认收到：

```text
PARAM=42\n
```

点击 <code>−</code> / <code>+</code> 会按步长修改并立即发送；手动输入后按 Enter 或点击发送按钮才发送。数值会限制在上下限内。

<a id="joystick"></a>

## 摇杆

### 默认配置

| 属性       | 默认值                   |
| ---------- | ------------------------ |
| 模板       | <code>X={x},Y={y}</code> |
| X / Y 范围 | -100～100                |
| 步长       | 1                        |
| 发送方式   | 连续发送                 |
| 松手回中   | 开启                     |

例如移动到 X=25、Y=-40，设备默认收到：

```text
X=25,Y=-40\n
```

<code>{x}</code>、<code>{y}</code> 分别替换为量化后的坐标。连续发送固定按 100ms 节流；开启回中后，松手还会发送中心坐标 <code>X=0,Y=0</code>。

### 设备端示例

```c
if (sscanf(line, "X=%d,Y=%d", &x, &y) == 2) {
    drive(x, y);
}
```

负数和逗号不是合法 HEX 内容，因此默认摇杆模板应使用 TEXT。

<a id="sequence"></a>

## 命令序列

### 默认配置

```text
AT
AT+GMR
```

命令间隔默认 100ms，可配置为 0–60000ms。运行后设备默认依次收到：

```text
AT\n
（等待 100ms）
AT+GMR\n
```

每个非空编辑行是一条独立命令，每条都会单独应用全局编码和换行；空行忽略。某条发送失败时停止后续命令。

当前版本只按固定间隔发送，不等待设备 ACK，也不支持条件分支。涉及升级、擦除等关键流程时，请把间隔留足并先单步验证。

<a id="gauge"></a>

## 能量槽

### 设备要输出什么

```text
{"battery":78}
```

在“数据”页选择 JSON 并应用，然后把组件“接收通道 key”填为 <code>battery</code>。

默认配置：

| 属性 | 默认值         |
| ---- | -------------- |
| 范围 | 0–100          |
| 单位 | <code>%</code> |
| 方向 | 横向           |

数据流：<code>设备 → JSON 解析为 battery=78 → 映射到 0–100 能量槽</code>。

低于最小值或高于最大值时显示会限制在槽体范围内；单位只负责显示，不要让设备发送 <code>"78%"</code>。

<a id="value"></a>

## 接收数值

### 设备要输出什么

```text
{"temp":25.3}
```

把“接收通道 key”填为 <code>temp</code>，单位可填 <code>°C</code>。设备后续每收到一个有效 <code>temp</code> 值，组件显示最新值；尚无有效值时显示 <code>--</code>。

数据流：<code>设备 → JSON 解析为 temp → 显示最新数值</code>。

组件只接受解析后的 number。<code>{"temp":"25.3"}</code> 是字符串，不会生效。

<a id="indicator"></a>

## 状态灯

### 设备要输出什么

```text
{"ready":1}
```

把“接收通道 key”填为 <code>ready</code>。默认阈值为 0.5：

```text
ready >= 0.5  → 点亮
ready < 0.5   → 熄灭
```

设备应输出数值 <code>0</code>/<code>1</code>，不要输出 JSON 布尔值 <code>true</code>/<code>false</code>，因为数据解析只保留数值字段。

<a id="serial-log"></a>

## 串口日志

### 设备要输出什么

串口日志不要求 JSON 或数值通道，任何能被接收分帧切开的文本都可以显示：

```text
boot ok
temp=25.3
motor started
```

数据流：<code>设备字节 → 接收分帧 → RX 日志</code>。它不经过“数据解析”。

方向可选“全部”“仅接收 RX”“仅发送 TX”。组件复用当前数据来源的日志、文本/HEX 显示、时间戳格式、复制、虚拟滚动和导出能力。

若多条日志粘在同一行，调整接收分帧，而不是数据解析格式。

<a id="yt-chart"></a>

## YT 实时波形

### 设备要输出什么

设备连续逐行输出同一时刻的一组数值：

```text
{"ch1":1.20,"ch2":3.40}
{"ch1":1.25,"ch2":3.32}
{"ch1":1.31,"ch2":3.18}
```

在“数据”页应用 JSON 后，在组件中绑定 <code>ch1</code>、<code>ch2</code>。最多绑定 6 个通道。

数据流：<code>每个解析样本 → 以接收时间为 X → 各通道数值为 Y</code>。

默认显示最近 200 点，可配置 10–2000 点；默认直线连接，也可选平滑曲线。显示点数只是可视范围，不改变设备采样率。

<a id="fft-chart"></a>

## FFT 频谱

### 设备要输出什么

FFT 输入是**连续的时域采样值**，不是频率/幅值列表：

```text
{"signal":0.00}
{"signal":0.31}
{"signal":0.59}
{"signal":0.81}
```

在“数据”页应用 JSON，绑定 <code>signal</code>，并在图表设置中填写正确采样率。例如设备每秒输出 1000 个样本，采样率设为 1000Hz。

```text
设备时域采样 → signal 通道历史 → FFT 窗口 → 频谱
```

| 属性       | 默认值    |
| ---------- | --------- |
| 显示点数   | 1024      |
| 可绑定通道 | 最多 6 个 |
| 点数范围   | 10–2000   |

### 常见错误

- 设备输出 <code>{"frequency":50,"magnitude":1.2}</code>：这不是本组件需要的输入。
- 只发送一个样本：FFT 需要连续样本窗口。
- 采样间隔不稳定或采样率配置错误：频率轴会不准确。
- 每行塞入整个数组：JSON 数组不会被解析，应逐采样输出，或使用 JustFloat 帧表示同一时刻的多个通道。

<a id="xy-chart"></a>

## XY 二维曲线

### 设备要输出什么

每一帧必须同时包含一个 X 和一个 Y：

```text
{"x":0.30,"y":0.80}
{"x":0.35,"y":0.76}
{"x":0.41,"y":0.70}
```

在组件中分别绑定 X 通道 <code>x</code> 和 Y 通道 <code>y</code>。同一解析帧里的两个值会组成一个轨迹点。

默认显示最近 200 点，可配置 10–2000 点。

### 常见错误

- X、Y 分两行发送：两行是两个采样，不能组成预期点。
- 只绑定一个通道：组件无法绘制。
- 用 YT 期待按真实 X 值绘图：YT 的横轴是接收时间；需要真实 X 值时用 XY。

<a id="imu-3d"></a>

## IMU 3D

IMU 3D 支持“欧拉角直驱”“原始六轴融合”和“四元数直驱”三种输入，并可再叠加一个旋转。所有模式都要求相关字段出现在同一采样帧；缺少字段时组件上方会列出缺失的通道 key。

### 欧拉角直驱

设备每行输出：

```text
{"roll":10.2,"pitch":-3.1,"yaw":45.0}
```

默认绑定：

| 旋转轴 | 通道 key           | 默认单位 |
| ------ | ------------------ | -------- |
| Roll   | <code>roll</code>  | deg      |
| Pitch  | <code>pitch</code> | deg      |
| Yaw    | <code>yaw</code>   | deg      |

如果设备输出弧度，把角度单位改为 rad。不要一边发送弧度、一边保持 deg。

设备端示例：

```c
printf("{\"roll\":%.3f,\"pitch\":%.3f,\"yaw\":%.3f}\n",
       roll_deg, pitch_deg, yaw_deg);
```

### 原始六轴融合

设备每行输出：

```text
{"ax":0.01,"ay":0.02,"az":1.00,"gx":0.2,"gy":-0.1,"gz":0.0}
```

默认绑定：

```text
加速度：ax / ay / az
陀螺仪：gx / gy / gz
陀螺单位：dps
兜底采样率：100Hz
互补滤波系数：0.98
```

- 三轴加速度可以使用 g 或 m/s²，但必须使用同一单位。
- 陀螺仪可选择 dps（°/s）或 rad/s。
- 采样率可配置 1–10000Hz；时间戳异常时使用该值作为兜底。
- 滤波系数范围 0–1，越接近 1 越依赖陀螺仪。
- 修改六轴通道、采样率、滤波系数或陀螺仪零偏后，应用会基于当前保留的样本重新计算姿态。
- 六轴没有磁力计，Yaw 长时间运行会漂移，这是传感器限制。

设备端示例：

```c
printf("{\"ax\":%.4f,\"ay\":%.4f,\"az\":%.4f,"
       "\"gx\":%.3f,\"gy\":%.3f,\"gz\":%.3f}\n",
       ax, ay, az, gx, gy, gz);
```

### 四元数直驱

设备每行输出：

```text
{"qw":0.9239,"qx":0,"qy":0,"qz":0.3827}
```

- 默认绑定 <code>qw</code> / <code>qx</code> / <code>qy</code> / <code>qz</code>，四个分量分别绑定通道，设备按 wxyz 还是 xyzw 顺序输出都可以。
- 自动归一化；四个分量全为 0 时视为无效（例如传感器还没完成初始化）。
- 显示的 Roll / Pitch / Yaw 按 ZYX 顺序换算，Pitch 接近 ±90° 时 Roll 与 Yaw 会合并，但 3D 姿态仍然正确。

设备端示例：

```c
printf("{\"qw\":%.5f,\"qx\":%.5f,\"qy\":%.5f,\"qz\":%.5f}
",
       q.w, q.x, q.y, q.z);
```

### 叠加旋转

在组件属性底部打开“叠加旋转”，可在输入姿态之上再合成一个旋转。常见用法：云台上的 IMU 叠加偏航电机角度，机械臂某一级的姿态叠加上一级关节角度，或用固定值补偿传感器安装角度。

- **表示方式**：欧拉角（Roll / Pitch / Yaw，可选角度或弧度）或四元数（W / X / Y / Z，自动归一化）。
- **来源**：每个分量可单独选择“通道”或“固定值”，可以混用，例如只有 Yaw 来自电机角通道，其余为 0。
- **叠加位置**：
  - 本体坐标系（输入 × 叠加）：绕传感器自身的轴再转，适合安装角补偿。
  - 世界坐标系（叠加 × 输入）：绕固定的外部轴转，适合叠加底座或上一级关节的转角。
  - 两个旋转绕同一根轴时两种位置结果相同；绕不同轴时结果不同，以实际机械结构为准。
- 叠加使用的通道同样必须出现在同一采样帧。

例如偏航电机角度从 <code>motor</code> 通道输出：

```text
{"roll":1.2,"pitch":-0.5,"yaw":20.0,"motor":30.0}
```

叠加方式选欧拉角，Yaw 选通道 <code>motor</code>，Roll / Pitch 为固定值 0，组件显示的 Yaw 为 50°。

### 校准

- “当前姿态归零”用于修正安装角度，三个偏移默认都是 0。
- 六轴模式保持设备静止后可执行“静止校准”，使用最近 200 个样本估算陀螺仪零偏。
- 校准不能修复错误的单位、轴方向或通道 key。

### 常见错误

- 只输出 <code>roll</code>，缺少 pitch/yaw。
- 四元数分量绑定错位，例如把 <code>qx</code> 绑到了 W。
- 六轴字段分散在多行。
- key 大小写不一致，例如输出 <code>Roll</code>，却绑定 <code>roll</code>。
- 陀螺仪实际是 rad/s，组件仍配置为 dps。
- 设备输出字符串数值，例如 <code>{"gx":"0.2"}</code>。

## 画布与配置共用限制

- 运行模式会隐藏组件库和组件属性，让控制画布使用完整宽度。
- 编辑模式使用浮动组件属性面板；拖动面板标题可调整位置，点击面板右上角可收起，再通过顶部“组件属性”按钮展开。未选择组件时会提示先点击画布中的组件。
- 点击顶部“前往设置”会在弹窗中打开当前来源的既有配置，关闭后立即继承最新连接与解析状态。
- 窄窗口会默认收起组件库；在编辑模式下点击顶部“组件库”按钮即可展开或再次收起。
- 组件保存宽度范围为 200–2400，高度范围为 96–2000。
- YT、FFT、XY 显示点数范围为 10–2000。
- YT、FFT 最多绑定 6 个通道。
- YT、FFT 右上角的“自适应”按钮可恢复 X/Y 自动范围；XY 曲线始终自动适配数据范围。
- 控制面板自动保存在本机，也可导入/导出 JSON。
- 当前配置版本为 version 4；旧 version 3 网格配置会自动迁移。

## 快速排查顺序

1. 确认数据源已连接。
2. 发送组件先在主日志查看 TX 内容；接收组件先确认 RX 有完整帧。
3. 接收组件到“数据”页检查解析预览并点击“应用解析”。
4. 对照预览出的通道 key，逐字检查组件绑定。
5. 最后再核对范围、单位、采样率和阈值。

如果 RX 文本本身就不完整，先修接收分帧；如果预览没有通道，先修解析格式；只有预览成功且 key 正确后，才需要检查组件属性。
